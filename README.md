## 自己PR・志向性

Webフロントエンドを中心に15年の開発経験があり、仕様・UXの検討からUIの設計・実装まで一貫して関わることを得意としています。ユーザーが「説明なしで使える」プロダクトを一つの基準として、使いやすさを追求してきました。

動画プレイヤーのライブラリ選定やジョイスティックUIのスクラッチ開発など、ユーザー体験と実現性の両面から最適な技術を選択し、プロダクトとして形にしてきました。

現在はAI英語学習サービス「abceed」のWebチームリーダーとして、自ら開発を行いながら、採用・技術選定・仕様調整・プロジェクト推進まで幅広く担っています。

また、AIを開発・レビューに活用するだけでなく、定型業務の自動化やチームで再利用できる仕組みづくりにも取り組み、開発プロセス全体の生産性向上を進めています。

## この先やりたいこと・大切にしたいこと

- **フロントエンド技術でプロダクト価値を引き上げる：**
  UIを実装するだけでなく、仕様やUXの検討段階から関わり、技術的な知見を活かしてユーザーが「説明なしで使える」プロダクトを実現したい

- **AI × 開発プロセスの進化：**
  AIを単なるコーディング支援としてではなく、仕様検討・設計・実装・レビューなど開発プロセス全体に取り入れ、エンジニアがプロダクトやユーザーに向き合う時間を増やしたい

- **技術とプロジェクトの両面から開発をリードする：**
  自ら実装・技術判断を担いながら、要件整理や仕様調整、タスク分解、関係者との調整まで関わり、プロダクト開発を前に進めたい

- **仕事と家庭の両立：**
  仕事にしっかり向き合いながら子どもとの時間も大切にし、家庭と両立しながら継続的に成果を出せる柔軟な働き方を重視したい

#### AI英語学習サービス「abceed」のWebフロントエンド開発

**期間：** 2021年3月 〜 現在
**役割：** フロントエンドリード

**概要：**
AI英語学習サービス「abceed」のWebフロントエンド開発をリード。ユーザー向け機能・管理画面の設計・実装に加え、PdM・デザイナーと連携した仕様整理やUI/UX改善、技術選定まで担当。

**課題と取り組み：**

##### Webに最適化した仕様・UI設計

- iOS / Androidアプリを中心に設計された仕様・デザインについて、リロード時の状態管理、ナビゲーションガード、複数ウィンドウ利用などWeb固有のユースケースを洗い出し、PdMと仕様を具体化
- アプリ向けデザインをそのまま実装するのではなく、デザイナーと連携してPCを含むWeb環境で使いやすいUIへ調整
- 担当外を含むプロジェクトについてもデザインや実装後の挙動を積極的に確認し、レスポンシブ表示、例外時のレイアウト、仕様で明示されていないユースケースなどをフィードバック

##### 映画・ドラマを使った英語学習機能の動画プレイヤー開発

- DRM対応とフレーズ単位の高速シークを両立する動画プレイヤーが必要だった
- hls.jsでプロトタイプを構築してUI/UXを検証後、DRM対応のためVideo.jsを採用
- 高速シーク時の再生停止問題を検証し、最終的にShaka Playerへ移行。DRM対応とシームレスなフレーズ再生を両立
- 詳しくは[abceed webの映画・ドラマ機能開発で使用した動画ライブラリの変遷](https://qiita.com/umi_kappa/items/f91eb2ed1ea3e0594992)をご覧ください

**技術スタック：** TypeScript, Vue.js, Vuex, Pinia, Vite, webpack, Vitest, Storybook, Chromatic, GitHub Actions, Shaka Player

#### Webフロントエンドチームのリード・開発プロセス改善

**期間：** 2021年3月 〜 現在
**役割：** チームリーダー

**概要：**
Webフロントエンドチームの立ち上げ期から、プロジェクト推進、採用、開発・レビュー環境の整備などを担当。自ら開発にも携わりながら、チーム全体の開発をリード。

**課題と取り組み：**

##### プロジェクト推進・役割分担

- チーム立ち上げ期は、要件・仕様整理、技術調査、UI/UX検討、URL設計、Issue作成、アサイン、PRレビュー、QA前検証までプロジェクト推進を幅広く担当
- その後、開発量の増加に合わせて、仕様整理やレビューを含むプロジェクト推進をメンバーへ段階的に移譲
- 現在は各プロジェクトの進行状況やメンバーの課題を継続的に把握し、必要に応じて仕様・技術面の支援や調整を担当

##### AIを活用した開発プロセス改善

- Claude Codeを日常的な開発に導入し、要件をもとにした設計・実装プランの策定から、実装・テスト・コードレビューまで開発プロセス全体で活用
- API関連ファイルの一括生成やPRレビューなど、繰り返し発生する開発業務を再利用可能なClaude CodeのSkillとして自動化
- Skillをリポジトリで共有し、チームメンバーとアイデアを持ち寄って議論・改善しながら、チーム共通の開発プロセスとして継続的に整備

##### コンポーネント開発・レビュープロセス改善

- 複雑なアプリケーション上で目的のコンポーネントを確認するために、画面遷移や状態の再現が必要だった
- Storybookの導入を提案し、アプリケーション全体を操作せずコンポーネント単位でUI・挙動を確認できる開発環境を整備
- メンバーからの提案をもとにChromaticを活用した運用をチームで整備し、Visual Regression Testingによる意図しないUI差分の検出や、オンラインのStorybookを利用したPRレビューを実現

##### フロントエンドエンジニア採用

- シニアクラスのフロントエンドエンジニア採用で、コーディング試験の改善・運用と技術面談を担当
- AIによる実装支援の普及を踏まえ、実装力だけでなく曖昧な要件を整理して仕様に落とし込む力も評価できるよう試験内容を改善

#### 車両遠隔操作システムのWebアプリケーション開発

**期間：** 2019年1月 〜 2019年3月
**役割：** フロントエンド開発

**概要：**
顧客企業の重機をスマートフォンから遠隔操作できることを示す技術デモとして、持ち運び可能なラジコンカーをWebアプリケーションから操作するシステムを開発。顧客先でのデモを想定し、説明なしでも直感的かつスムーズに操作できるUIが求められた。

**課題と取り組み：**

- ジョイスティックUIにHammer.jsを採用したが、操作レスポンスやマルチタッチへの対応に課題があった
  - タッチ操作に最適化したジョイスティックUIをスクラッチで開発し、直感的な操作性を実現
- デザイナーと協業し、操作に失敗した場合でも復帰しやすいフローなど細部のUXを検討
  - 納品時にはクライアントが説明なしで操作できるUIを実現

**技術スタック：** TypeScript, React, Redux, Storybook

#### オフライン環境向け車載器Webアプリケーションの技術検証・開発

**期間：** 2018年9月 〜 2018年12月
**役割：** フロントエンド開発（設計〜実装）

**概要：**
インターネット接続がない環境でも、自社製車載器のデータをスマートフォンから確認できるプロダクトの技術検証・開発を担当。

**課題と取り組み：**

- ネットワークを介さずスマートフォンから車載器のデータを取得する方法として、Web Bluetooth APIを用いたプロトタイプを開発
  - 当時は事例や情報が少ない中、仕様を調査しながらBLEによるデータ通信を実装
  - 実機での検証を通じて、プロダクトとして求める安定性を満たすことが難しいことを確認し、技術選定の判断材料を提供
- 検証結果を踏まえてチームで方式を見直し、車載器側から配信されるWebアプリケーションにスマートフォンから直接アクセスする構成へ移行
  - フロントエンドの設計・実装を担当し、インターネット接続に依存せず車載器の情報を確認できるWeb UIを実現

**技術スタック：** TypeScript, React, Redux, Storybook, Web Bluetooth API

## 技術研鑽・個人開発

### 個人開発（2026年4月 〜 現在）

**ポジション：** フロントエンドエンジニア

#### [PeakRM](https://github.com/umi-kappa/peak-rm)（トレーニング記録・1RM可視化Webアプリ）

**期間：** 2026年4月 〜 現在
**役割：** 企画・設計・実装

**概要：**
自身のトレーニング記録を紙で管理していることや、インターバル計測に別のタイマーアプリを使用している不便を解消するため、トレーニング記録・推定1RMによる成長の可視化・インターバル管理を一つにまとめたWebアプリを個人開発。企画、仕様整理、UX設計、UIデザイン、アーキテクチャ設計、実装まで一貫して担当。現在リリースに向けて開発中。

**課題と取り組み：**

- **AIを活用した開発における設計・UIの一貫性**
  - [仕様書](https://github.com/umi-kappa/peak-rm/blob/main/docs/spec.md)・[コーディング規約](https://github.com/umi-kappa/peak-rm/blob/main/docs/conventions.md)・[デザインドキュメント](https://github.com/umi-kappa/peak-rm/tree/main/docs/design)を整備し、AIを活用した開発でも設計判断・実装方針・UIの一貫性を維持できる開発環境を構築
  - Figmaなどのデザインツールを使用しない代わりに、UIの方針や判断基準をデザインドキュメントとして管理

- **トレーニング中の利用を想定したUI/UX設計**
  - セット間の短い時間でも迷わず操作できることを重視し、記録入力・成長の確認・インターバル計測を一つのアプリ内で完結できるUIを設計
  - 自身が実際にジムで行っている記録・インターバル管理をもとに、利用シーンから必要な機能と操作フローを設計

- **ローカルファースト・オフライン対応**
  - リリースまでの開発コストを抑えつつ、通信環境が安定しないジムでも利用できるよう、バックエンドへの常時接続を前提としない構成を採用
  - IndexedDB（Dexie）によるローカルファースト設計とPWA化により、ログイン不要・オフラインで利用できるアプリケーションを実装

**技術スタック：** TypeScript, Vue.js, Vite, IndexedDB (Dexie), PWA, Chart.js, Vitest, Storybook, Chromatic, GitHub Actions
