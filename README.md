## 自己PR・志向性

インタラクティブコンテンツ開発を含め15年の実務経験があり、Webフロントエンドエンジニアとして13年以上、ユーザーが「説明なしで使える」UIの設計・実装を得意としています。\
キャリア初期にはFlash / ActionScript 3.0を用いたインタラクティブコンテンツ開発に約3年携わり、現在までユーザー体験を起点としたフロントエンド開発を続けてきました。\
動画プレイヤーのライブラリ選定からジョイスティックUIのスクラッチ開発まで、ユーザー体験のために技術選択を妥協しない姿勢を大切にしています。\
現在はAI英語学習サービス「abceed」のWebチームリーダーとして、チーム立ち上げ期から採用・技術選定・プロジェクト管理までを幅広く担い、チームの成長を牽引してきました。\
限られたリソースの中でも技術的に妥協しない開発を推進するために、Claude CodeやCodeRabbitなどAIツールによる開発効率化を武器に、チームと個人の生産性を最大化することに注力しています。

#### AI英語学習サービス「abceed」のWebフロントエンド開発

**期間：** 2021年3月 〜 現在
**役割：** フロントエンドリード

**概要：**
AI英語学習サービス「abceed」のWebフロントエンド開発をリード。abceed本体のユーザー向け機能および管理画面の設計・実装を担当。デザインチームとの仕様調整を積極的に行い、操作感・実装観点からのUI改善を推進。

**課題と取り組み：**

- 映画・ドラマを使った英語学習機能の新規開発で、DRM対応の動画プレイヤー実装が必要だった
  - hls.jsでプロトタイプを素早く構築し、映画会社とのUI/UX検証を実施
  - DRM（Widevine）対応でVideo.jsに移行したが、フレーズ単位の高速シークで動画が停止する問題が発生
  - 最終的にShaka Playerへ移行し、DRM対応とフレーズ単位のシームレスな再生を両立
  - 詳しくは[abceed webの映画・ドラマ機能開発で使用した動画ライブラリの変遷](https://qiita.com/umi_kappa/items/f91eb2ed1ea3e0594992)をご覧ください
- Vue 2で構築された既存コードベースに技術的負債が蓄積していた
  - 新規機能開発と並行しながらVue 3への段階的な移行を推進中

**AI活用による開発効率化（現在も積極的に検証・導入中）：**

- Cursor、CodeRabbitによるコーディング・PRレビューの効率化
- Claude Codeを活用したテスト自動生成、Figma MCPによるスタイリング
- Git Worktreeでの並行開発により、レビュー待ちの間も別タスクを進行

**技術スタック：** TypeScript, Vue.js (Vuex / Pinia), Vite, webpack, Vitest, Storybook, GitHub Actions, Figma

#### 車両遠隔操作システムのWebアプリケーション開発

**期間：** 2019年1月 〜 2019年3月
**役割：** フロントエンド開発

**概要：**

- デザイナーと協業し、失敗してもフォールバックできるフローなど細部のUXにこだわった
  - 納品時にクライアントが説明なしで操作できるUXを達成

**技術スタック：** TypeScript, React, Redux, Jest, Storybook

#### 車載器ステータス確認用Webアプリケーション開発（Bluetooth）

**期間：** 2018年9月 〜 2018年12月
**役割：** フロントエンド開発（設計〜実装）

**概要：**
自社製車載器のステータス情報をスマートフォンで確認するWebアプリケーションを開発。インターネット接続がない環境でも動作するよう、Web Bluetooth APIを活用したオフライン対応を実現。

**課題と取り組み：**

- ネットワーク接続がない環境でも動作する要件があった
  - ServiceWorker（Workbox）によるローカルキャッシュとWeb App Manifestでオフライン起動を実現
  - Web Bluetooth（BLE）でハードウェアとの無線通信（Read・Notification）を実装
- Web Bluetooth APIの事例情報が極めて少なく、仕様も策定途中だった
  - BLE仕様を読み込み、未知のAPIを一から検証しながら機能要件を満たす実装を完成させた

**技術スタック：** TypeScript, React, Redux, ServiceWorker, Storybook

## 技術研鑽・個人開発

### 個人開発（2026年4月 〜 現在）

**ポジション：** フロントエンドエンジニア

#### [PeakRM](https://github.com/umi-kappa/peak-rm)（トレーニング記録・1RM可視化Webアプリ）

**期間：** 2026年4月 〜 現在
**役割：** 企画・設計・実装

**概要：**
BIG3（ベンチプレス・スクワット・デッドリフト）のトレーニング記録を管理し、推定1RMの成長推移を可視化するWebアプリを個人開発。企画、仕様整理、UX設計、UIデザイン、アーキテクチャ設計、実装、テストまで一貫して担当している。

**課題と取り組み：**

- AIを活用しながらも、設計方針と品質基準を一貫させる必要があった
  - Claude Codeを活用して、仕様検討・設計レビュー・実装・コードレビューを実施
  - [仕様書](https://github.com/umi-kappa/peak-rm/blob/main/docs/spec.md)・[コーディング規約](https://github.com/umi-kappa/peak-rm/blob/main/docs/conventions.md)・[デザインドキュメント](https://github.com/umi-kappa/peak-rm/tree/main/docs/design)を整備し、設計判断と実装方針を管理
- トレーニング中でも迷わず操作できるUIを実現する必要があった
  - Claude Designで作成したデザイン案を叩き台に、操作性・視認性・一貫性を改善しながら実装
- ログインやネットワーク接続に依存せず、継続して使えるアプリにする必要があった
  - IndexedDB（Dexie）によるローカルファースト設計とPWA化により、ログイン不要・オフライン利用を実現
- 継続的に品質を担保する必要があった
  - Storybookによるコンポーネント開発とインタラクションテスト、Vitestによるロジックテストを実施
  - GitHub Actions、Chromatic、pre-commit hookを用いた継続的な品質チェックを整備

**技術スタック：** TypeScript, Vue.js, Vite, IndexedDB (Dexie), PWA, Vitest, Storybook, Chromatic, GitHub Actions
